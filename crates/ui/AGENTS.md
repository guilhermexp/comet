# zeron-ui — o app gpui

Pai: [`../AGENTS.md`](../AGENTS.md)

## Purpose

O viewport: shell (sidebar de spaces + abas), transcript, composer, painel de terminal, pane de diff, settings, markdown próprio e o kit de animação. Renderiza estado do mirror direto, com notificação por entrada alterada.

## Ownership

Dona de tudo que é pixel. **Não** é dona de comportamento que precisa sobreviver à janela fechada — isso é `zeron-engine`. Regra derivada compartilhada com a engine mora em `zeron-proto::view`, não aqui.

## Local Contracts

- O círculo de contexto mostra percentual ao lado (— quando desconhecido), com warning em 75% e critical em 90%. Tooltip observa AppState, deriva o Chat selecionado em cada render e mostra tokens exatos usados/capacidade/restantes; ausência não é zero. Só o arco é clampado a 100%, nunca o percentual. Estilo glass e clique /compact permanecem; OMP continua exibindo a última medição reportada até a próxima consulta ao runtime.

- Enter vazio durante run ativo é no-op; interrupção continua pelo Stop explícito. Seleção de blocos de código participa do registro compartilhado do Markdown e conserva linhas vazias/copiar grupos inline.
- Tipografia de terminal e código/diff é device-local e independente (`terminalFontFamily/Size`, `codeFontFamily/Size`). Terminal aceita só catálogo fixed-width; código aceita o catálogo completo. Alterações invalidam medidas e atualizam geometria/scroll; defaults do fork permanecem 13px no terminal, 12.5px no código e 14px/24px no corpo de conversa.

- A varinha de Changes fica dentro do campo de commit e habilita com arquivos staged. Geração compartilha contexto/roteamento nos modos Orchestrator e Workers, mostra spinner nativo e erro inline; bloqueia novas operações Git até assentar. O input preserva múltiplas linhas. Resposta só preenche o mesmo contexto com a mesma revisão de texto; edição manual ganha, inclusive editar e desfazer. Trocar contexto cancela a tarefa de UI. Commit continua explícito.

- Fragmentos de caixas inline Markdown usam discriminador de animação próprio por bloco e offset (`nested_ix`), inclusive células de tabela. `RowVeil` é keyed pelo índice do elemento, não por `row_key`; reutilizar zero reinicia a transparência a cada fragmento e mantém texto invisível durante streaming.

- A reserva de espaço do turno usa `ListState::set_tail_reservation` antes do layout; nunca padding recalculado após paint. Wheel/touch libera o hold sincronamente; retorno ao fim mantém follow, e scroll para cima preserva a posição quando a resposta cresce.

- History tem aba própria no painel de utilitários: busca com debounce e geração, navegação/colapso no grafo, pontas de branches e colunas persistidas (visibilidade, largura, ordem e autor). Preservar âncora/seleção ao trocar visualização. Perder foco na busca não limpa o filtro: o clique deve selecionar a mesma linha que estava visível. Workers usam cwd local explícito; Chat remoto mantém targetDeviceId. Preferências são gravadas no store atual, nunca por cópia stale do Shell.

- `browser/` é uma surface própria de páginas HTTP(S), com WebKit no macOS e abertura externa nos demais sistemas. Abas pertencem ao Chat, compartilham store efêmero só dentro do perfil e liberam páginas/subscriptions ao fechar. Browser não substitui `file_preview/`: documentos continuam no loader nativo existente. Browser usa proxy local apenas para hosts de preview registrados e conserva atalhos personalizados. Geometria da animação é avaliada uma vez por frame para o native clip acompanhar o painel.

- Changes compartilha a mesma aba nos modos Orchestrator e Workers; o contexto Worker usa o checkout do projeto selecionado e a engine autoriza pelo link do checkout com um Space deste device.

- Os controles de Files (ocultos, novo arquivo, nova pasta, busca e expandir/recolher) ficam à direita do título no cabeçalho do próprio painel Files, nunca na faixa de abas Details/Files/Changes.

- Files de um Chat/Space registrado usa RPC no device dono e `DirectoryCache` para reconciliar só diretórios afetados, sem descartar expansão/scroll. Paginação tem ação Load more. Requests incluem ignored para preservar a política local de mostrar pastas operacionais, filtrando apenas hidden conforme preferência e saídas estruturais já negadas. Contextos locais de Workers e Chats sem Space mantêm seu scanner local. O executor de mutação (`FileMutation`) escolhe o mesmo backend que a leitura (`workspace_file_source`): RPC `call_as` com `targetDeviceId` quando há `WorkspaceTarget`, senão helpers jaulados de `file_tree.rs` no cwd local — nunca sintetiza um target falso. Os cinco pontos locais passam pelas mesmas funções de `zeron-proto` que a engine (`validate_workspace_component` / `validate_workspace_create_name` / `unique_copy_name` / `sibling_name_taken`); rename/move recusam destino existente e não sobrescrevem. `checked_existing` caminha componente a componente com `symlink_metadata` e recusa symlink na folha e no meio — não usa `canonicalize` no relativo, para não mutar o alvo de um link. Copy local cria destino com `create_dir`/`create_new` e só faz rollback do que criou. Menu de contexto (botão direito, `menu_at` no ponteiro) e toolbar New File/New Folder cobrem create/rename/delete/move/copy, clipboard interno de cut/copy, Copy Path/Relative Path no clipboard do SO, e Finder/Terminal só no checkout local. Delete pede confirmação e é permanente. Rename/move retargetam seleção e preview; delete de diretório fecha o preview de qualquer descendente (prefixo de path). Trocar contexto limpa clipboard, prompt de delete, inline e `file_mutation_error`, e cancela fetch/watch. Atalhos ⌘C/⌘X/⌘V/F2/Delete/Escape na árvore focada (`#details-files-pane`). Versões antigas exibem estado de atualização necessária, sem fallback local para path remoto.

- O **Changes** (source control) mora na aba Changes do Files explorer do upstream (`files/mod.rs` `ExplorerTab::Changes`), ao lado de Explorer — não mais como terceira aba da Details Sidebar. O estado continua do `DetailsSidebar` e é desenhado pela view `details_sidebar::view::SourceControlPane` (uma instância no `Shell`, entregue a cada explorer em `add_files_surface`), então commit/stage/sync são um estado só. `DetailsTab::SourceControl` persistido de versões antigas abre em Details. Métricas seguem o Files (rows 27px, nome 11,5px, botões 26px, controles 24px). Conteúdo: branch, ahead/behind, staged/unstaged, commit e sync/publish. Derivação pura mora em `details_sidebar/source_control.rs`. Clique num arquivo emite `OpenWorkingTreeDiff` e o shell foca o painel Changes existente no escopo working tree. O painel de diff existente continua sendo só o viewer; staging pertence a esta aba. Watch de status cancela na troca de contexto, no mesmo padrão de Files. Diretório sem git mostra estado vazio, sem botão de ação. Discard confirma nomeando o arquivo e avisa quando apaga untracked. Controles de mensagem/Commit/Sync Changes ocupam a largura, com ahead/behind junto de Sync. Staged vazio é oculto; seções têm disclosure e badge. Rows usam Material Icon Theme, basename destacado, diretório secundário truncável e tooltip completo; status à direita (U azul para untracked, ! vermelho para conflito). Stage/unstage/discard são ícones com tooltip revelados no hover, interrompendo propagação para não abrir diff. O estado de disclosure é local ao contexto e reseta ao trocar checkout.
- Documentos remotos de texto usam o mesmo loader e renderer do preview nativo (Markdown, HTML isolado, código, CSV/TSV). Fonte remota fica presa ao contexto/device; Open in local fica oculto, e erro remoto não tenta ler o mesmo path na máquina local. Links locais absolutos externos ao checkout continuam no resolvedor anterior. Fechar a última aba libera a fonte remota.

- `AppState` retém timestamps frescos de Sessions/Devices, mas o watcher só notifica quando metadata visível, status, erro, contexto ou presença efetiva muda. Heartbeats idênticos não redesenham a árvore; ticks de device ainda aposentam indicadores de sessões remotas stale.

- Headers de tools Workers usam o catálogo local de apresentação (`WorkersToolCatalog`) publicado pelo `WorkersModel` em `AppState`, com igualdade exata por ID. `project_id` vira ação + chip `@nome` (mono, `code_wash`, raio 5px); `launch_worker` também mostra o ícone/nome do preset identificado por `preset_id`. Alvos `session_id` mostram ícone/título do Worker e têm precedência sobre projeto/preset. Ícone vem de `runtime_icon_path`, com runtime ativo antes de provider para Workers. Snapshot substitui nomes/ícones antigos e notifica apenas ao mudar. Só Chats do device local usam esse catálogo; host desconhecido/remoto ou ID ausente conserva identificação técnica, sem adivinhar pelo projeto/comando. O chip de lançamento identifica o preset, não um Worker resultante inferido. Invocação, resultado, export e execução mantêm os IDs originais. Não ler disco nem consultar Workers durante render.

- Headers de eval mostram apenas o título (ou nome da tool), sem Evaluating/Evaluated; MCP mostra servidor e tool sem Calling tool/Called tool. Skill mostra o identificador recebido em `skill`/`path`/`name` ao lado do label; hub mostra a operação/alvo já derivados, sem Ran/Running hub. Preservar ícones, erros e detalhes expansíveis.

- `questions.rs` é o presenter nativo do histórico de perguntas: `Asking question…` em carregamento, pergunta + espera enquanto o composer coleta input, e card `Answer/Answers` com perguntas e respostas por id. `ask`/`AskUserQuestion`/`request_user_input` passam por ele; requests com texto exato no intervalo da tool substituem sua apresentação sem duplicação. Histórico sem resposta persistida indica `Answer not recorded`; seleção pulada indica `Skipped`. A UI não reconstrói respostas por índice nem cria outro painel interativo.

- **Modelo de novos Chats é a última escolha explícita**, feita no draft ou dentro de um Chat existente. `Pickers::pick_model` salva harness + id completo (incluindo provider) em `composer-defaults.json` antes de aplicar a configuração ao destino. Navegar por Chats ou carregar catálogos não substitui essa escolha. A configuração própria de cada Chat continua independente.
- **Troca de modelo dentro de um Chat deixa marcador no transcript.** `Pickers::pick_model` compara o modelo efetivo com o escolhido e, quando muda num Chat existente, dispara `Mutate noteModelSwitch` com os LABELS do catálogo (o engine não tem catálogo de modelos). Entry de role `system` vira `RowKind::Notice` — divisor centralizado entre hairlines, nunca bolha de usuário nem bloco de assistente —, e marcador seguido de outro marcador não renderiza (`is_superseded_notice`): trocar três vezes sem enviar nada mostra só a última.
- **Controle de Ref / Branch Switcher vive exclusivamente no card Workspace da Details Sidebar**: O footer do composer não renderiza nenhum controle de branch (mantendo apenas o cluster de modelo e esforço). A seleção e troca de branch é feita pelo trigger interativo `[branch ▾]` no card Workspace de `details_sidebar`, abrindo o popover de branches com badges de status (`local`, `remote`, `default`) e permitindo `git checkout` via `methods::SWITCH_REF` ou retarget via `methods::SET_CHAT_CWD` em chats ativos. **Bloqueio por `Working` tem uma fonte só**: `live_ref_switch_blocked(indicator)` (puro; o chamador injeta `now` em `indicator_for`) decide, e `Pickers::live_ref_block` o aplica ao Chat vivo resolvido por `live_ref_chat` — trigger desabilitado, rows inertes com o motivo no popover, e a mesma guarda no topo de `pick_ref` como defesa (um run pode começar com o popover aberto). O label vem de `RepoTarget.branch` (o `chat.branch` do `DetailsContext`), nunca de `ref_label`. Row de Ref com worktree num Chat vivo diz `worktree · new conversation` (`worktree_row_badge`): é Retarget, resume é escopo de cwd, e a ADR 0003 exige o custo visível antes do clique. Árvore suja não tem trava própria — o erro do git cai na faixa de erro do popover.

- **O `@` do composer é um menu de dois níveis**: a raiz traz a entrada `Projects` acima dos resultados de `SearchFiles`; abri-la troca o popup pela lista de projetos, filtrada pelo mesmo token. A fonte dos projetos é o **registro único** (`AppState.spaces` × `devices`, os mesmos projetos do chat MCP `list_projects` e de Settings → Projects), relido a cada abertura com o device dono na linha — não o ledger de checkouts nem o daemon de Workers. Aceitar insere um link local: `zeron-file:` com path relativo ao workspace, `zeron-project:` com path absoluto e o nome do projeto como label. Menção de projeto é **referência textual**: não troca cwd, device nem projeto-alvo do chat.

- gpui vem do snapshot vendorizado em `third_party/zui` (proveniência em `third_party/zui-upstream.toml`; entradas `gpui` / `gpui_platform` / `gpui_tokio` no `Cargo.toml` raiz apontam por `path`). **Não usamos as crates GPL do Zed** (`markdown`, `ui`, `theme`, `editor`) — markdown, componentes e tema são nossos. Puxar uma delas é problema de licença, não de gosto. Não editar o conteúdo do vendor: correção de gpui entra no clone `zui` e re-vendoriza.
- As macros legadas de `objc 0.2` emitem `cfg(feature = "cargo-clippy")`; `Cargo.toml` declara somente esse valor no `unexpected_cfgs`, mantendo o lint ativo para qualquer outro cfg inesperado.
- `icons::Assets` também é a fonte virtual dos fallbacks pedidos pelo renderer SVG: os paths IBM Plex Sans e Lilex são aliases para os bytes já embutidos de Geist e Geist Mono. Não adicionar arquivos de fonte duplicados.
- Knobs de captura (`ZERON_OPEN_ROUTE`, `ZERON_OPEN_DIALOG`, `ZERON_OPEN_PICKER`, `ZERON_FORCE_GATE`, `ZERON_DEMO_UPLOAD`, `ZERON_DEMO_TRAJECTORY`) só valem com `ZERON_UI_CAPTURE=1|true|yes|on` e passam **sempre** por `capture::knob`. Toda nova `SettingsSection` entra também no parser de `ZERON_OPEN_ROUTE`, para a própria página continuar alcançável no QA nativo. `std::env::var` direto para uma knob é proibido: exportada uma vez num shell, ela seguia todo `cargo run` daquele terminal — o app abriu na página Accounts por dias. Run normal boota no chat, ponto.
- Cards de widgets de Details usam raio de 8 px só no cabeçalho do `widget_card` compartilhado, pintado com o mesmo fill do composer (`theme.composer_glass_bg()`). O corpo fica sem fill nem hairline, no plano do pane.
- **Visibilidade dos widgets do Details é escolha persistida do usuário**: o gear (`SETTINGS_MINIMALISTIC`) no header da aba Details abre um dropdown (`anchored_menu_below_end` sobre `widgets_menu: Popup<()>`) com um checkbox por card de `TOGGLEABLE_WIDGETS` (Workspace / Workers / To-dos / Usage — ids batendo com o `widget_card`). Marcar/desmarcar grava em `DetailsSidebarPreferences::hidden_widgets` (set global de ids ocultos) e emite `PreferencesChanged` → save debounced do shell; no boot as prefs voltam por `DetailsSidebarState::new`. `render_details` pula cada card cujo id esteja em `hidden_widgets`.
- Tema (`theme.rs`) suporta light e dark. Token que sumiu do upstream (ex: `white_alpha`) se remapeia pro equivalente que o upstream aplicou no código gêmeo — não se recria localmente, senão o light mode fica com wash.
- Temas built-in e importados são resolvidos por `zeron-theme`; Appearance persiste tema, accent e política de superfície separadamente. Tipografia de interface é configurável, mas superfícies de código continuam em Geist Mono; troca de família/tamanho invalida medição do transcript.
- Frost por variante: `Theme::glass()` lê `frost_alpha` com `GLASS_ALPHA` como fallback (off-macOS continua opaco); `frosted(...)` em `popover.rs`/`composer.rs` lê `frost_blur_radius` com `MENU_BLUR`/`16.0` como fallback, clampado em `0.0..=64.0` tanto em `frost_blur_or` quanto em `current_frost_blur`; a janela pede o raio declarado via `Theme::window_background_blur_radius` → `Window::set_background_blur_radius` na abertura e em `appearance::reapply_window_background` (`None` sem declaração = material AppKit); a coluna da sidebar em `shell.rs` pula `wash(0.05)` quando `flat_shell` é verdadeiro. Wash autoral de input (`a < 0.20`) sobrevive ao frost intacto — `Hsla::opacity` multiplica e não pode reaplicar o alpha. `composer_glass_bg` usa a metade real só nesse wash; input tipo prato (`a ≥ 0.20`) conserva a cobertura quadrática histórica (`0,5 · a²`), calibrada a olho. Reverse video (SGR 7) resolve `CellColor::Background` como glifo contra o canvas achatado. Não achatar seeds `#rrggbbaa` em hex opaco — o renderer compõe o alpha.
- Com o preset de accent **Gray** selecionado, código inline no Markdown ganha `code_wash` com cantos arredondados. O underlay existente pinta pelas posições dos glifos, inclusive com quebra de linha, abaixo da seleção; não insere espaços nem altera medição. Outros presets, prosa e fenced code mantêm a apresentação anterior.
- **Accent e Appearance são os tipos de `zeron-theme`, não cópias.** `theme.rs` reexporta `AccentPreset as AccentColor` e `Appearance`; o modelo carrega os aliases serde de settings antigo (`violet`/`indigo`/`red`/`purple` → `Zeron`, `teal` → `Cyan`), e a paleta continua aqui como função livre `accent_tokens(accent, appearance)`, com `appearance_from_window` mapeando o `WindowAppearance` do gpui. Reintroduzir um enum local devolve as duas conversões que existiam só para atravessar o seam.
- Animação é camada de **paint**: `with_animation` sobre opacidade nunca altera layout. `prefers-reduced-motion` é honrado.
- Altura de linha em code block = linhas × line-height, independente do highlight; o highlight roda time-sliced em background e entra como run de texto (paint-only).
- Transcript é por **bloco**, não por mensagem: id estável `msgId#blockId`, turno vivo não splitado, re-split na persistência. Eco otimista compartilha o id cunhado no cliente pra persistência não piscar.
- **Delete de Chat no Orchestrator confirma na própria row da sidebar**, no
  mesmo padrão dos Workers (`Cancel` + ação perigosa no lugar da sessão). Não
  há modal central. Rename de Chat continua diálogo.
- **A entrega do export mora no shell, a formatação não**: as seis ações do menu resolvem as entries e escolhem destino; `chat_export.rs` continua puro. O transcript vem da memória SÓ quando a linha clicada é a selecionada (`export_reads_memory`) — qualquer outra abre um `WatchDocMessages` transitório e consome apenas o frame `Reset`, porque exportar o chat errado é uma falha silenciosa que produz arquivo plausível. Conclusão normal de download ou cópia para o clipboard é silenciosa (sem toast intrusivo); falhas e perdas parciais saem pelo `toast` overlay flutuante (`toast.rs`), nunca por `notify::post`: banner de desktop é canal de background e é suprimido justamente com o app em foco.
- **Central de Notificações Unificada (toast.rs)**: Todas as notificações transitórias essenciais do app (erros de mutação/sign-in, falhas de export) são entregues pelo overlay de toasts flutuante no canto inferior direito (`bottom-right`), com auto-dismissal temporizado, sem botões de ação, sem poluir o rodapé da sidebar. Ações puras de clipboard (cópia de links/IDs/chat) e downloads de export operam silenciosamente sem toasts redundantes. A placa usa os mesmos tokens do `ContextUsageTooltip`: frost `10/16`, raio `10px`, hairline `theme.border`, fill `theme.composer_glass_bg()` (`toast_card_background`). O ícone carrega o tom semântico, não a borda. Update de CLI de agente NÃO é toast: é a ilha da Home (`shell/harness_updates.rs`, com **Update all** fork) e os badges dos Presets de Workers, ambos lendo `AppState::harness_updates` do coordenador do engine.
- **Chat Transcript Export usa duas fontes explícitas**: `ExportDoc.messages` é uma projeção pura de `&[SessionMessageEntry]`, enquanto o índice de artifacts recebe também os CLI Workers já projetados pelo `WorkersModel`. O shell captura ambos antes de `cx.spawn`; falha no join de workers degrada para lista vazia **e o resultado sai como `Incomplete`**, nunca como sucesso limpo — arquivo entregue sem o índice de workers é exatamente o arquivo plausível que o notice existe pra denunciar. Nunca lê Run Journal, resolve `output_ref`/`diff_ref` ou importa gpui/I/O; tools usam `zeron_proto::view::tool_chip_content`, e só o `ToolCall` já sanitizado decide quais comando/path aparecem.
  `ExportDoc.messages` usa tipos próprios (`ExportMessage`/`ExportPart`/`ExportTool`), nunca `SessionMessageEntry` bruto: output, diff, refs, reasoning, input e workflow deixam de ser representáveis antes dos três renderers. Workers carregam título + session id e preservam a ordem determinística de `project_chat_workers`; Markdown e texto normalizam campos de Artifact para uma linha e usam fences dinâmicos, enquanto JSON preserva o valor original. Sem worker, os três formatos permanecem byte-idênticos ao export anterior.
- `MessagePart::Image` é uma saída do transcript, não atividade de tool: a row usa `entry#part`, preserva `owner/path/name/mime_type`, mantém a imagem fora do `TurnSteps` recolhido e o export registra a referência em Markdown/Text/JSON. O loader limita bytes/dimensões, confere MIME contra a assinatura e normaliza PNG/GIF/JPEG/WebP (incluindo primeiro frame de GIF animado); a chave de cache inclui o MIME esperado para não reutilizar um anexo genérico sem validação.
- Chips GitHub/YouTube existem só em mensagens de usuário já enviadas: `url_chips.rs` segmenta e projeta o texto uma vez em `rows_for_entry`, e a row cacheia spans clicáveis. O paint só consome esses spans; input, assistente e outras URLs continuam texto, a pontuação final fica fora do chip e a mensagem persistida nunca muda.
- Mensagens do usuário seguem o upstream: bolhas à direita, no máximo 80% da coluna, com `theme::user_bubble_bg()`, sem header fixo nem overlay de continuação. Texto longo recolhe em cinco linhas renderizadas, seguido de `...` e `Show more` / `Show less` dentro da bolha; expansão é inline e preserva a leitura. Menções, chips de URL, badges, anexos/Appshots e aparência pendente continuam disponíveis. O runway posiciona apenas a row original do novo envio.
- O blur do pill do composer usa `COMPOSER_CORNER_RADIUS`, igual à borda: raios diferentes deixam texto do transcript sem blur nos cantos internos. Corrigir esse recorte não altera o fill nem a geometria do campo.
- O fill de todo surface que fica **no lugar do pill do composer** — o próprio pill, o tooltip da janela de contexto (`ContextUsageTooltip`), o toast (`toast::toast_card_background`), o painel de pergunta (`#question-panel`) e a faixa de Live Voice (`composer-live-voice-strip`) — é o **mesmo**: todos vêm de `theme.composer_glass_bg()` (o `input_glass_bg` afinado a ~metade da cobertura), com hairline `theme.border`. Mudar a transparência de um exige mudar todos pela mesma fonte — o teste `toast_card_matches_the_context_tooltip_glass` trava o par.
- `TurnSteps` e a projeção de mudanças de arquivo mantêm ids estáveis; previews de Write/Edit renderizam somente o conteúdo limitado que veio do doc.
- Tool comum em turno assentado nunca fica viva: `rows_for_entry` força `resolved`/`is_error` quando `status != Streaming`; subagente com `subagent_ref` conserva seu lifecycle independente, e só o estado legado sem referência recebe a guarda de falha. A engine assenta as parts no recovery, mas todo doc escrito antes disso ainda carrega `resolved: false` — a guarda é o que cura o histórico.
- `TurnSteps` expandido não adiciona recuo horizontal aos filhos: cards de edição/código conservam as bordas do input.
- Uma hairline discreta de largura da coluna fica ao final de `TurnSteps`, depois de todos os filhos quando aberto e depois do resumo quando recolhido, separando a resposta final sem repetir divisores entre tools/commentary.
- `TurnSteps` só existe em turno assentado: enquanto `status == Streaming` os eventos ficam no nível principal com seus próprios disclosures, e o fold nasce ao assentar reaproveitando os ids das rows vivas.
- Tools comuns renderizam diretamente sua row. Subagentes aparecem como **linhas de ciclo de vida** no estilo do Codex, não como chips. Na posição do spawn fica uma linha por subagente, com avatar de 18px, nome e `started working`, mais um spinner enquanto está `Running` (`render_subagent_start`). A linha de fim (`<nome> finished` / `failed`) é uma row própria, `RowKind::SubagentEnd`, inserida por `place_subagent_end_rows` depois da row que contém a part apontada por `subagentEnd`. Um fim que caiu em outra entry é distribuído por `subagent_end_placements` e entra na chave de cache das duas entries (`SubagentEndPlacement::key`). Sem `subagentEnd`, ou com uma entry que não existe mais, a linha de fim fica logo abaixo da de início. As duas linhas abrem o subagente, como o chip abria. O estado mora no `WorkersModel` (ao lado do resto da seleção) e é persistido pela observação que o Shell já roda sobre esse model, em `UiSettings::workers_project_filter`; filtro apontando pra projeto que sumiu cai para `All projects` no `apply_snapshot` (`filter_after_snapshot`), senão a árvore abriria vazia sem caminho de volta. Sem tag `@ device`: as raízes de Workers são só os Spaces deste device; o valor do filtro é o Space id.
- **Worktree com sessões não tem linha própria na sidebar de Workers.** `render_project` achata a worktree: as sessões sobem para o nível das sessões do projeto pai (`depth - 1`), cada uma com a marca `WORKER_BRANCH` em `theme.success`, e o tooltip da marca mostra a branch. O nome da branch fica no painel de detalhes e na titlebar. Worktree sem sessão mantém o cabeçalho, senão sumiria da lista junto com o menu de contexto e o quick launch dela. A linha de "Projects worked" no Details usa a mesma marca verde para projeto worktree (`WorkedProject.branch`), com a mesma regra de `workers_titlebar`.

Faltando ele, o card fica montado para sempre — `menu_out` leva a opacidade a zero e o overlay `.occlude()` que a fase de saída pinta continua engolindo TODO clique na sidebar embaixo. Na tela isso não parece um menu travado, parece a sidebar inteira desbotada e morta (reportado assim: "fica um fade e não consigo apertar mais"). Todo `if popup.begin_close() { ... }` no crate agenda o reap dentro do `if`; o filtro de Workers foi o único que esqueceu.
- **PRs de Workers usam os mesmos watches/cache e `sidebar_show_pull_request` do Orchestrator**. `WorkersModel::publish_change_request_targets` inclui checkouts locais e worktrees do working set (sessões não arquivadas ou navegação explícita), não todos os registros do ledger. Grupos não são alvos. Header, lookup e assinatura usam `WorkersProject::change_request_branch`, preferindo `git_branch` atual; ausência de badge não prova ausência de PR. `change_request_for_checkout` preserva matching por cwd/branch e canonicalização só no miss.
- **A sidebar de Workers ordena por SETTLE, não por update — só terminar reordena.** `updated_at_unix_ms` não serve de chave: ele anda com o heartbeat do host e com cada frame de output, então ordenar por ele fazia rows e pastas trocarem de lugar a qualquer chamada sem nada ter terminado. `session_settled_at` (`presentation.rs`) é a chave: worker com turno **em voo** (`starting`/`working` num `running`) congela em `created_at_unix_ms` — segura a posição em que foi lançado por toda a run, não importa quanto output produza; qualquer outro estado (turno feito, `blocked`, processo morto) sai por `idle_since_unix_ms` — o stamp da última atividade REAL, que por construção não anda com heartbeat nem repaint idêntico, e é o instante em que o worker parou (fallback `updated_at_unix_ms` quando o host ainda não tem evidência; sessão morta não recebe mais heartbeat, então esse stamp já é final). Desempate `created_at_unix_ms` desc, depois id asc: comparador **total** porque a sidebar repinta a cada 120ms e um parcial deixaria timestamps iguais reembaralhando. A row imprime idade com a MESMA chave, então ordem e label nunca se contradizem — "13s" num worker assentado lê "terminou 13s atrás", e um em voo mostra a idade do lançamento. Projetos ordenam pelo settle mais novo do **subtree** (`project_activity` dobra a chave pai acima, senão todo grupo — que não tem sessão própria — afundava abaixo dos projetos que ele contém), em DFS pra filho nunca desgrudar do pai, com a ordem persistida do host como desempate entre projetos sem atividade nenhuma. Cap de rows em `SESSION_ROW_CAP`; nada disso grava.
- **Sessão que terminou e não foi aberta carrega o dot de unread, e ele é azul, não o accent.** `session_indicator` tratava `state != "running"` como `Exited` antes de olhar `unread`, então o caso que dá sentido ao dot — processo saiu, output nunca aberto — era exatamente o que ficava sem nenhum sinal na row. Hoje `unread` vence nessa saída **quando ela foi normal** (`Restarting` continua na frente por relaunch em voo; com a sessão viva, `Busy`/`Attention` continuam ganhando). Saída anormal não entra nesse dot: `blocked` segue `Attention` mesmo com a sessão fora, e quem morreu em `working`/`starting` renderiza `Exited` — o dot diz "terminou, é só ler", e dizer isso de um worker que caiu é mentira. A cor sai de `project_folder_tint(Some("blue"), dark)` e não de `theme.accent`: o significado é "pronto pra você olhar" e precisa ler igual em qualquer família de accent que o usuário escolha, com par light/dark que sobrevive aos dois fundos. Quem produz e limpa `unread` é o host Unpeel (`mark_read` na seleção); a UI só projeta.

A linha filha de worktree usa `WORKER_BRANCH` no lugar da pasta/chevron, com nome da branch atual e seus Workers abaixo. PR confirmado usa `SidebarIcon`, com detalhes no tooltip; não repetir glifos Git por Worker. A árvore continua baseada nos parents do snapshot; nomes de worktree e PR usam `change_request_branch`. - O Files pane do details sidebar **não consulta `.gitignore`**, global excludes nem `.ignore`: a raiz de um workspace é diretório de estado vivo tanto quanto checkout, e honrar as regras de ignore escondia justamente o que o pane existe pra mostrar (`~/.orchestrator` ignora `logs/`, `sessions/`, `data/`, `brain-source/`). Ruído estrutural (`.git`, `node_modules`, `target`, `dist`, `build`, caches) é negado por **nome** em `file_tree::DENIED_DIRECTORIES`/`DENIED_FILES`, e o watcher de recência reusa a mesma regra por `is_denied_relative`.
- Symlink de diretório é **pasta não atravessável**: o `file_type` do link diria "arquivo", então a classificação stata o alvo (`entry_is_dir`) enquanto `follow_links(false)` continua barrando a descida. Link quebrado permanece arquivo.
- Recência de arquivo é **event-sourced**, nunca mtime: o scan não lê timestamp nenhum. Evento do watcher marca o path com o instante em que **chegou**, e o tier decai em 10s/60s/180s (`recency.rs`) com tick de 5s que também poda a última marca — sem poda notificada a linha final ficaria com tint velho. O decaimento é lido no render contra wall clock, não via `with_animation`: gpui reinicia o clock por element id em remount e as rows são reconstruídas em todo rescan.
- Rescan disparado por watcher é **silencioso** (`refresh_files`): manter `LoadState::Loading` piscava o pane vazio a cada save. Debounce de 500ms coalesce a rajada de eventos.
- A faixa de status mostra o **motivo** da falha quando a session row traz um (`view::run_failure_text`), truncado na própria linha; `"Run failed"` é só o fallback de quando não há motivo. A constante crua escondia mensagens acionáveis que a engine já tinha em mãos e journalava.
- **Escape no composer é gesto de duas etapas**: um Esc mantém tudo que já fazia (fecha o popup de menção, volta uma página do painel de pergunta); dois Escs dentro de `DOUBLE_ESCAPE_WINDOW` param o run vivo — o botão Stop pelo teclado. O painel de pergunta **na primeira página não consome** o Esc: ele cobre o composer inteiro, inclusive o Stop, então essa é a única saída de uma pergunta cujo run travou.
- **Selecionar ou limpar Chat nunca encerra Live Voice.** A call continua presa ao Chat de origem na engine durante navegação, perda de foco e minimize; a UI volta a projetar o estado corrente ao retornar. Elegibilidade em run ativo vem exclusivamente do probe da engine/capability do OMP — a UI não bloqueia `Working`/`AwaitingInput` por conta própria. End/Escape no Chat ativo e os lifecycle gates da engine continuam sendo os donos do stop.

Cache ignorado ou arquivo produzido pelo setup pode impedir a exclusão; nesse caso a UI mostra o caminho preservado e o motivo, para que o usuário decida o que salvar e limpe o checkout conscientemente.
- O handoff de setup de um worktree novo consulta o host até o ciclo de vida assentar (limite de 1h: a engine só avisa após 720s e continua esperando, e as fases se encadeiam); um corte curto escondia o erro ou terminal de setup que chegasse depois. O polling é leve, a cada 250ms no primeiro minuto e 2s depois, e não inicia outro build.
- Na criação de worktree para Live Voice, `setupError` impede iniciar a call e entra no rollback seguro; `copyWarning` chega pelo `CreateWorktreeOutcome` e aparece como aviso na sidebar após o início.

O pill mantém só live-voice/attach/send. **Clicar no anel dispara `/compact`** (`compact_now`) pela mesma via de `send`, só com chat selecionado e run parado — mid-run o comando viraria steer. O rascunho do input volta depois do envio, já que `send` limpa o campo. Quem marca a compactação é o **`send`**, não o clique (`is_compact_command`): digitar `/compact` na mão passa pelo mesmo detector. Enquanto ela corre, `AppState::compacting` guarda o tamanho de contexto anterior e **o próprio `/compact` no transcript vira a linha de status** (`Transcript::render_compact_command`: divisor com spinner "Compacting conversation…" no lugar do card; some quando o marcador `Context compacted · …` chega logo abaixo; sem marcador, fica um aviso discreto `/compact`). O footer do composer não mostra mais label de compactação, a linha `/compact` não vira cabeçalho fixo de turno e, no envio, não ganha o runway de prompt (`ComposerEvent::Sent { compacting }` → `jump_to_bottom`): no topo ela ficava sob o prompt fixo do turno anterior; `shell::finish_compaction` limpa isso em qualquer saída de Working (run que errou ou parou pra perguntar não pode deixar o label girando) e, só no edge Working→Idle, grava o divisor `Contexto compactado · antes → depois` via `Mutate noteMarker`. O `depois` é capturado imediatamente no evento de conclusão: o harness publica usage antes de `Done`. Não atrasar essa leitura, que poderia capturar o próximo turno. O marcador aceita aumento e igualdade de tokens; o círculo acompanha o mesmo snapshot sem esperar um turno novo.
- Ordem de atalho é ordem pintada: salto numérico e Ctrl+Tab consomem `sidebar_visible_order`, incluindo sort escolhido, agrupamento por device, promoção do device local e exclusão dos grupos colapsados. Popover com foco suprime os atalhos.

O listener arquiva e só então `stop_propagation`; sem sessão pra fechar ele **não** interrompe, e o ⌘W volta a fechar a janela. `⇧⌘A` continua sendo o arquivar do Chat no Orchestrator. Atalho que depende de route só é seguro em superfície que a route de fato escolhe. `archive_selected_session` move a seleção **antes** de despachar (o round-trip leva um refresh) e reusa `selection_after_remove`.

Arraste e layout responsivo compartilham o mesmo orçamento, sem persistir excesso invisível. A manipulação direta interrompe os tweens das duas colunas. Ref não-imagem vira chip de documento e **nunca** dispara load: mandá-la pelo caminho de imagem pedia ao device uma figura que não decodifica e a faixa virava uma fileira de molduras tracejadas vazias. A faixa quebra em linhas conforme a largura disponível, sem scroll horizontal; os itens conservam dimensões estáveis entre estados de load e o virtualizer mede a altura resultante da faixa.

É irmão do pill (`container.children(strip)`) e `target_height = base_height + comment_strip_h` não soma altura de anexo nenhuma — a altura do pill é independente da contagem de anexos. Medidas provisórias não emitem notificação: `ViewportChanged` sai do prepaint com geometria final ou clamp de scroll alterado. O epoch de medição continua avançando no cache hit para preservar a histerese compacto↔expandido.

Markers permanecem visíveis, inputs acima de 10.000 caracteres pulam o scanner, e somente métricas do shaping base dirigem o flip compacto↔expandido.

Com match exato essas entradas ficavam cacheadas pra sempre e todo bloco de thinking congelava no comprimento do primeiro paint, cortado no meio da palavra. `flats`/`code` não guardam hash de conteúdo — a chave é a única validade, então chave derivada nova exige que o prefixo continue sendo o id da row. `retain_rows` mantém apenas preparação das rows renderizadas (viewport/overdraw e descendentes), incluindo suas árvores secundárias; não cachear cenas que pulem o registro por frame de links e seleção.

Raw Reveal (`RevealState`) é estritamente efêmero no dispositivo local e nunca persiste nem sincroniza; troca de seleção ou fechamento limpa o estado. `ROW_HEIGHT` no ledger é fixo (`px(26.0)`) e nenhum estado altera a altura da linha. Dado ausente renderiza como `Unavailable` ou `Unsettled`, nunca como zero ou vazio fabricado.

## Work Guidance

- **Workers / Projects:** ambas as telas agrupam checkouts pelo projeto
  (`space_id`) — branch, remote e basename não são identidade. Na sidebar de
  Workers as raízes são os Spaces locais (`WorkersModel::spaces`, observado do
  `AppState`), com o nome do registro; o principal registrado é a row raiz
  executável e, sem ele, a raiz é contêiner de apresentação (path vazio, sem
  cwd nem menu de grupo) — não existe mais "Principal not registered". Projeto
  de outro device nunca é raiz de Workers. Checkout sem link entra em
  `Association pending`. O filtro da sidebar guarda o Space id
  (`filter_key`/`filter_root`). A migração única do estado Workers para o
  registro roda na primeira anexação da engine com Spaces sincronizados
  (`Shell::start_registry_migration`, uma vez por processo); falha vira toast
  de erro.
  Projects seleciona explicitamente o checkout para Path/Config/Reveal/Auto Doc;
  erro de probe ou pasta ausente desabilita ações de filesystem.
- **Archive checkout** preserva arquivos e sessões; sessões paradas saem do
  working set, mas Workers ativos/selecionados continuam acessíveis. Não
  encaminhar archive ao handler de remoção física. PR pertence ao cwd e branch
  atualmente observados; detached/ausente não reutiliza badge antigo. Cobertura:
  `workers::workspace`, `workers::project_menu`, `settings::projects` e
  `change_requests`; comprovação visual em
  `docs/verification/2026-09-18-workers-project-identity.md`.

- "Não atualizou na tela" começa em `zeron-doc` (mirror), não aqui.
- Não há harness de render: mudança visual se valida rodando `scripts/dev-demo.sh` e olhando. Screenshot antes de dizer pronto.
- Recuperação de foco do Shell verifica o dispatch tree montado após layout: prefere o composer quando presente e usa a raiz focável quando o handle anterior ficou desmontado. Não substitui o retorno de first responder AppKit do preview nativo. Seleção no transcript suspende o follow já no mouse-down, cancelando animação e viewport pendente antes de arrastar.
- Toda raiz de `track_focus` precisa de `.id()` + `.role()` (mais `aria_label` / `aria_value` quando o controle carrega texto). Sem role o gpui deixa o elemento fora da árvore AccessKit, loga `a11y: focused element … has no accessibility node` a cada mudança de foco, e a tecnologia assistiva anuncia a janela inteira em vez do controle focado.
