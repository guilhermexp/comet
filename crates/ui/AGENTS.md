# zeron-ui — o app gpui

Pai: [`../AGENTS.md`](../AGENTS.md)

## Purpose

O viewport: shell (sidebar de spaces + abas), transcript, composer, painel de terminal, pane de diff, settings, markdown próprio e o kit de animação. Renderiza estado do mirror direto, com notificação por entrada alterada.

## Ownership

Dona de tudo que é pixel. **Não** é dona de comportamento que precisa sobreviver à janela fechada — isso é `zeron-engine`. Regra derivada compartilhada com a engine mora em `zeron-proto::view`, não aqui.

## Local Contracts

- A reserva de espaço do turno usa `ListState::set_tail_reservation` antes do layout; nunca padding recalculado após paint. Wheel/touch libera o hold sincronamente; retorno ao fim mantém follow, e scroll para cima preserva a posição quando a resposta cresce. O estado `has_landed` mantém o handoff com o sticky do fork.

- History tem aba própria no painel de utilitários: busca com debounce e geração, navegação/colapso no grafo, pontas de branches e colunas persistidas (visibilidade, largura, ordem e autor). Preservar âncora/seleção ao trocar visualização. Perder foco na busca não limpa o filtro: o clique deve selecionar a mesma linha que estava visível. Workers usam cwd local explícito; Chat remoto mantém targetDeviceId. Preferências são gravadas no store atual, nunca por cópia stale do Shell.

- `browser/` é uma surface própria de páginas HTTP(S), com WebKit no macOS e abertura externa nos demais sistemas. Abas pertencem ao Chat, compartilham store efêmero só dentro do perfil e liberam páginas/subscriptions ao fechar. Browser não substitui `file_preview/`: documentos continuam no loader nativo existente. Browser usa proxy local apenas para hosts de preview registrados e conserva atalhos personalizados. Geometria da animação é avaliada uma vez por frame para o native clip acompanhar o painel.

- Files de um Chat/Space registrado usa RPC no device dono e `DirectoryCache` para reconciliar só diretórios afetados, sem descartar expansão/scroll. Paginação tem ação Load more. Requests incluem ignored para preservar a política local de mostrar pastas operacionais, filtrando apenas hidden conforme preferência e saídas estruturais já negadas. Contextos locais de Workers e Chats sem Space mantêm seu scanner local. O executor de mutação (`FileMutation`) escolhe o mesmo backend que a leitura (`workspace_file_source`): RPC `call_as` com `targetDeviceId` quando há `WorkspaceTarget`, senão helpers jaulados de `file_tree.rs` no cwd local — nunca sintetiza um target falso. Os cinco pontos locais passam pelas mesmas funções de `zeron-proto` que a engine (`validate_workspace_component` / `validate_workspace_create_name` / `unique_copy_name` / `sibling_name_taken`); rename/move recusam destino existente e não sobrescrevem. `checked_existing` caminha componente a componente com `symlink_metadata` e recusa symlink na folha e no meio — não usa `canonicalize` no relativo, para não mutar o alvo de um link. Copy local cria destino com `create_dir`/`create_new` e só faz rollback do que criou. Menu de contexto (botão direito, `menu_at` no ponteiro) e toolbar New File/New Folder cobrem create/rename/delete/move/copy, clipboard interno de cut/copy, Copy Path/Relative Path no clipboard do SO, e Finder/Terminal só no checkout local. Delete pede confirmação e é permanente. Rename/move retargetam seleção e preview; delete de diretório fecha o preview de qualquer descendente (prefixo de path). Trocar contexto limpa clipboard, prompt de delete, inline e `file_mutation_error`, e cancela fetch/watch. Atalhos ⌘C/⌘X/⌘V/F2/Delete/Escape na árvore focada (`#details-files-pane`). Versões antigas exibem estado de atualização necessária, sem fallback local para path remoto.

- A Details Sidebar tem terceira aba **Source Control** (`DetailsTab::SourceControl`): branch, ahead/behind, staged/unstaged, commit e sync/publish. Derivação pura mora em `details_sidebar/source_control.rs`. Clique num arquivo emite `OpenWorkingTreeDiff` e o shell foca o painel Changes existente no escopo working tree. Changes continua sendo só o viewer de diff, não o staging. Watch de status cancela na troca de contexto, no mesmo padrão de Files. Diretório sem git mostra estado vazio, sem botão de ação. Discard confirma nomeando o arquivo e avisa quando apaga untracked.
- Documentos remotos de texto usam o mesmo loader e renderer do preview nativo (Markdown, HTML isolado, código, CSV/TSV). Fonte remota fica presa ao contexto/device; Open in local fica oculto, e erro remoto não tenta ler o mesmo path na máquina local. Links locais absolutos externos ao checkout continuam no resolvedor anterior. Fechar a última aba libera a fonte remota.

- `AppState` retém timestamps frescos de Sessions/Devices, mas o watcher só notifica quando metadata visível, status, erro, contexto ou presença efetiva muda. Heartbeats idênticos não redesenham a árvore; ticks de device ainda aposentam indicadores de sessões remotas stale.

- Headers de tools Workers usam o catálogo local de apresentação (`WorkersToolCatalog`) publicado pelo `WorkersModel` em `AppState`, com igualdade exata por ID. `project_id` vira ação + chip `@nome` (mono, `code_wash`, raio 5px); `launch_worker` também mostra o ícone/nome do preset identificado por `preset_id`. Alvos `session_id` mostram ícone/título do Worker e têm precedência sobre projeto/preset. Ícone vem de `runtime_icon_path`, com runtime ativo antes de provider para Workers. Snapshot substitui nomes/ícones antigos e notifica apenas ao mudar. Só Chats do device local usam esse catálogo; host desconhecido/remoto ou ID ausente conserva identificação técnica, sem adivinhar pelo projeto/comando. O chip de lançamento identifica o preset, não um Worker resultante inferido. Invocação, resultado, export e execução mantêm os IDs originais. Não ler disco nem consultar Workers durante render.

- Headers de eval mostram apenas o título (ou nome da tool), sem Evaluating/Evaluated; MCP mostra servidor e tool sem Calling tool/Called tool. Skill mostra o identificador recebido em `skill`/`path`/`name` ao lado do label; hub mostra a operação/alvo já derivados, sem Ran/Running hub. Preservar ícones, erros e detalhes expansíveis.

- `questions.rs` é o presenter nativo do histórico de perguntas: `Asking question…` em carregamento, pergunta + espera enquanto o composer coleta input, e card `Answer/Answers` com perguntas e respostas por id. `ask`/`AskUserQuestion`/`request_user_input` passam por ele; requests com texto exato no intervalo da tool substituem sua apresentação sem duplicação. Histórico sem resposta persistida indica `Answer not recorded`; seleção pulada indica `Skipped`. A UI não reconstrói respostas por índice nem cria outro painel interativo.

- **Modelo de novos Chats é a última escolha explícita**, feita no draft ou dentro de um Chat existente. `Pickers::pick_model` salva harness + id completo (incluindo provider) em `composer-defaults.json` antes de aplicar a configuração ao destino. Navegar por Chats ou carregar catálogos não substitui essa escolha. A configuração própria de cada Chat continua independente.
- **Troca de modelo dentro de um Chat deixa marcador no transcript.** `Pickers::pick_model` compara o modelo efetivo com o escolhido e, quando muda num Chat existente, dispara `Mutate noteModelSwitch` com os LABELS do catálogo (o engine não tem catálogo de modelos). Entry de role `system` vira `RowKind::Notice` — divisor centralizado entre hairlines, nunca bolha de usuário nem bloco de assistente —, e marcador seguido de outro marcador não renderiza (`is_superseded_notice`): trocar três vezes sem enviar nada mostra só a última.
- **Controle de Ref / Branch Switcher vive exclusivamente no card Workspace da Details Sidebar**: O footer do composer não renderiza nenhum controle de branch (mantendo apenas o cluster de modelo e esforço). A seleção e troca de branch é feita pelo trigger interativo `[branch ▾]` no card Workspace de `details_sidebar`, abrindo o popover de branches com badges de status (`local`, `remote`, `default`) e permitindo `git checkout` via `methods::SWITCH_REF` ou retarget via `methods::SET_CHAT_CWD` em chats ativos, com guarda de bloqueio quando o agente estiver em estado `Working`.

- **O `@` do composer é um menu de dois níveis**: a raiz traz a entrada `Projects` acima dos resultados de `SearchFiles`; abri-la troca o popup pela lista de projetos, filtrada pelo mesmo token. A fonte dos projetos é o **ledger** (`project_ledger::read`, o que Settings → Projects mostra), lido em background a cada abertura — não `AppState::spaces` (que só tem o working set, e de todos os devices) nem o daemon de Workers. Aceitar insere um link local: `zeron-file:` com path relativo ao workspace, `zeron-project:` com path absoluto e o nome do projeto como label. Menção de projeto é **referência textual**: não troca cwd, device nem projeto-alvo do chat.

- gpui vem da extração `zeronsh/zui` pinado por rev no `Cargo.toml` raiz. **Não usamos as crates GPL do Zed** (`markdown`, `ui`, `theme`, `editor`) — markdown, componentes e tema são nossos. Puxar uma delas é problema de licença, não de gosto.
- As macros legadas de `objc 0.2` emitem `cfg(feature = "cargo-clippy")`; `Cargo.toml` declara somente esse valor no `unexpected_cfgs`, mantendo o lint ativo para qualquer outro cfg inesperado.
- `icons::Assets` também é a fonte virtual dos fallbacks pedidos pelo renderer SVG: os paths IBM Plex Sans e Lilex são aliases para os bytes já embutidos de Geist e Geist Mono. Não adicionar arquivos de fonte duplicados.
- Knobs de captura (`ZERON_OPEN_ROUTE`, `ZERON_OPEN_DIALOG`, `ZERON_OPEN_PICKER`, `ZERON_FORCE_GATE`, `ZERON_DEMO_UPLOAD`, `ZERON_DEMO_TRAJECTORY`) só valem com `ZERON_UI_CAPTURE=1|true|yes|on` e passam **sempre** por `capture::knob`. Toda nova `SettingsSection` entra também no parser de `ZERON_OPEN_ROUTE`, para a própria página continuar alcançável no QA nativo. `std::env::var` direto para uma knob é proibido: exportada uma vez num shell, ela seguia todo `cargo run` daquele terminal — o app abriu na página Accounts por dias. Run normal boota no chat, ponto.
- Cards de widgets de Details usam raio de 8 px só no cabeçalho do `widget_card` compartilhado, pintado com o mesmo fill do composer (`theme.composer_glass_bg()`). O corpo fica sem fill nem hairline, no plano do pane.
- **Visibilidade dos widgets do Details é escolha persistida do usuário**: o gear (`SETTINGS_MINIMALISTIC`) no header da aba Details abre um dropdown (`anchored_menu_below_end` sobre `widgets_menu: Popup<()>`) com um checkbox por card de `TOGGLEABLE_WIDGETS` (Workspace / Workers / To-dos / Usage — ids batendo com o `widget_card`). Marcar/desmarcar grava em `DetailsSidebarPreferences::hidden_widgets` (set global de ids ocultos) e emite `PreferencesChanged` → save debounced do shell; no boot as prefs voltam por `DetailsSidebarState::new`. `render_details` pula cada card cujo id esteja em `hidden_widgets`.
- Tema (`theme.rs`) suporta light e dark. Token que sumiu do upstream (ex: `white_alpha`) se remapeia pro equivalente que o upstream aplicou no código gêmeo — não se recria localmente, senão o light mode fica com wash.
- Temas built-in e importados são resolvidos por `zeron-theme`; Appearance persiste tema, accent e política de superfície separadamente. Tipografia de interface é configurável, mas superfícies de código continuam em Geist Mono; troca de família/tamanho invalida medição do transcript.
- Frost por variante: `Theme::glass()` lê `frost_alpha` com `GLASS_ALPHA` como fallback (off-macOS continua opaco); `frosted(...)` em `popover.rs`/`composer.rs` lê `frost_blur_radius` com `MENU_BLUR`/`16.0` como fallback, clampado em `0.0..=64.0` tanto em `frost_blur_or` quanto em `current_frost_blur`; a coluna da sidebar em `shell.rs` pula `wash(0.05)` quando `flat_shell` é verdadeiro. Wash autoral de input (`a < 0.20`) sobrevive ao frost intacto — `Hsla::opacity` multiplica e não pode reaplicar o alpha. Reverse video (SGR 7) resolve `CellColor::Background` como glifo contra o canvas achatado. Não achatar seeds `#rrggbbaa` em hex opaco — o renderer compõe o alpha.
- Com o preset de accent **Gray** selecionado, código inline no Markdown ganha `code_wash` com cantos arredondados. O underlay existente pinta pelas posições dos glifos, inclusive com quebra de linha, abaixo da seleção; não insere espaços nem altera medição. Outros presets, prosa e fenced code mantêm a apresentação anterior.
- **Accent e Appearance são os tipos de `zeron-theme`, não cópias.** `theme.rs` reexporta `AccentPreset as AccentColor` e `Appearance`; o modelo carrega os aliases serde de settings antigo (`violet`/`indigo`/`red`/`purple` → `Zeron`, `teal` → `Cyan`), e a paleta continua aqui como função livre `accent_tokens(accent, appearance)`, com `appearance_from_window` mapeando o `WindowAppearance` do gpui. Reintroduzir um enum local devolve as duas conversões que existiam só para atravessar o seam.
- Animação é camada de **paint**: `with_animation` sobre opacidade nunca altera layout. `prefers-reduced-motion` é honrado.
- Altura de linha em code block = linhas × line-height, independente do highlight; o highlight roda time-sliced em background e entra como run de texto (paint-only).
- Transcript é por **bloco**, não por mensagem: id estável `msgId#blockId`, turno vivo não splitado, re-split na persistência. Eco otimista compartilha o id cunhado no cliente pra persistência não piscar.
- **Delete de Chat no Orchestrator confirma na própria row da sidebar**, no
  mesmo padrão dos Workers (`Cancel` + ação perigosa no lugar da sessão). Não
  há modal central. Rename de Chat continua diálogo.
- **A entrega do export mora no shell, a formatação não**: as seis ações do menu resolvem as entries e escolhem destino; `chat_export.rs` continua puro. O transcript vem da memória SÓ quando a linha clicada é a selecionada (`export_reads_memory`) — qualquer outra abre um `WatchDocMessages` transitório e consome apenas o frame `Reset`, porque exportar o chat errado é uma falha silenciosa que produz arquivo plausível. Conclusão normal de download ou cópia para o clipboard é silenciosa (sem toast intrusivo); falhas e perdas parciais saem pelo `toast` overlay flutuante (`toast.rs`), nunca por `notify::post`: banner de desktop é canal de background e é suprimido justamente com o app em foco.
- **Central de Notificações Unificada (toast.rs)**: Todas as notificações transitórias essenciais do app (erros de mutação/sign-in, falhas de export e avisos de atualização de worker CLIs) são entregues pelo overlay de toasts flutuante no canto inferior direito (`bottom-right`), com auto-dismissal temporizado e suporte a botões de ação interativos, sem poluir o rodapé da sidebar. Ações puras de clipboard (cópia de links/IDs/chat) e downloads de export operam silenciosamente sem toasts redundantes. A placa usa os mesmos tokens do `ContextUsageTooltip`: frost `10/16`, raio `10px`, hairline `theme.border`, fill `theme.composer_glass_bg()` (`toast_card_background`). Toast de progresso (`UpdatingProgress`) leva o `mini_mono_spinner` à esquerda do título; o ícone carrega o tom semântico, não a borda.
- **Chat Transcript Export usa duas fontes explícitas**: `ExportDoc.messages` é uma projeção pura de `&[SessionMessageEntry]`, enquanto o índice de artifacts recebe também os CLI Workers já projetados pelo `WorkersModel`. O shell captura ambos antes de `cx.spawn`; falha no join de workers degrada para lista vazia **e o resultado sai como `Incomplete`**, nunca como sucesso limpo — arquivo entregue sem o índice de workers é exatamente o arquivo plausível que o notice existe pra denunciar. Nunca lê Run Journal, resolve `output_ref`/`diff_ref` ou importa gpui/I/O; tools usam `zeron_proto::view::tool_chip_content`, e só o `ToolCall` já sanitizado decide quais comando/path aparecem.
  `ExportDoc.messages` usa tipos próprios (`ExportMessage`/`ExportPart`/`ExportTool`), nunca `SessionMessageEntry` bruto: output, diff, refs, reasoning, input e workflow deixam de ser representáveis antes dos três renderers. Workers carregam título + session id e preservam a ordem determinística de `project_chat_workers`; Markdown e texto normalizam campos de Artifact para uma linha e usam fences dinâmicos, enquanto JSON preserva o valor original. Sem worker, os três formatos permanecem byte-idênticos ao export anterior.
- Chips GitHub/YouTube existem só em mensagens de usuário já enviadas: `url_chips.rs` segmenta e projeta o texto uma vez em `rows_for_entry`, e a row cacheia spans clicáveis. O paint só consome esses spans; input, assistente e outras URLs continuam texto, a pontuação final fica fora do chip e a mensagem persistida nunca muda.
- Cards do usuário são sticky por turno: um clone paint-only do renderer existente encosta no fim da titlebar (`STICKY_TURN_TOP_INSET_PX`) e é empurrado pelo próximo user row. A linha de leitura usa o mesmo inset; os 10px de respiro do runway de envio não entram no sticky, para não expor uma faixa de texto entre a barra e o card. A geometria é per-chat, não altera altura da lista, não substitui o runway e não duplica o original quando ele já ocupa a posição.
- A largura horizontal do sticky segue o campo de digitação: caixa central de 768px com padding de 16px e margens automáticas; não aplicar as margens de 48px da lista ao overlay. O inset vertical aprovado continua independente.
- O wrapper externo do sticky é transparente; a oclusão/blur e o bloqueio de mouse/hover subjacente ficam limitados ao card interno arredondado, enquanto wheel/touch continuam chegando ao transcript.
- O blur do pill do composer usa `COMPOSER_CORNER_RADIUS`, igual à borda: raios diferentes deixam texto do transcript sem blur nos cantos internos. Corrigir esse recorte não altera o fill nem a geometria do campo.
- O fill de todo surface que fica **no lugar do pill do composer** — o próprio pill, o card de mensagem do usuário (`transcript::user_message_card_background`), o tooltip da janela de contexto (`ContextUsageTooltip`), o toast (`toast::toast_card_background`), o painel de pergunta (`#question-panel`) e a faixa de Live Voice (`composer-live-voice-strip`) — é o **mesmo**: todos vêm de `theme.composer_glass_bg()` (o `input_glass_bg` afinado a ~metade da cobertura), com hairline `theme.border`. Mudar a transparência de um exige mudar todos pela mesma fonte — os testes `user_message_card_matches_the_composer_background` e `toast_card_matches_the_context_tooltip_glass` travam o par.
- `TurnSteps` e a projeção de mudanças de arquivo mantêm ids estáveis; previews de Write/Edit renderizam somente o conteúdo limitado que veio do doc.
- Tool comum em turno assentado nunca fica viva: `rows_for_entry` força `resolved`/`is_error` quando `status != Streaming`; subagente com `subagent_ref` conserva seu lifecycle independente, e só o estado legado sem referência recebe a guarda de falha. A engine assenta as parts no recovery, mas todo doc escrito antes disso ainda carrega `resolved: false` — a guarda é o que cura o histórico.
- Uma hairline discreta de largura da coluna fica ao final de `TurnSteps`, depois de todos os filhos quando aberto e depois do resumo quando recolhido, separando a resposta final sem repetir divisores entre tools/commentary.
- `TurnSteps` só existe em turno assentado: enquanto `status == Streaming` os eventos ficam no nível principal com seus próprios disclosures, e o fold nasce ao assentar reaproveitando os ids das rows vivas.
- Tools comuns renderizam diretamente sua row. Subagentes adjacentes vinculados à mesma chamada `task` registrada (IDs sintéticos `parent--child`) compartilham uma linha com pares clicáveis de avatar de 28px + nome, lado a lado, e status agregado; chamadas diferentes e spawns sem vínculo comprovado ficam separados. Status dos filhos continua independente da conclusão do pai. Não mostrar contagens intermediárias (`2 commands`, `1 read, 1 command`) no streaming nem dentro do turno aberto: contagem agregada só no resumo recolhível de `TurnSteps` ao concluir. Payloads individuais continuam expansíveis.
- Tarefas começam como resumos de uma linha, inclusive em streaming e dentro de `TurnSteps` expandido; expansão explícita revela os detalhes e permanece autoritativa por row id. Raciocínio mostra o header `Thinking` enquanto ativo e `Thought` ao concluir, com corpo aberto por padrão e seta sempre visível. Escolha manual de recolher/abrir permanece respeitada por row id.
- Tools recolhidas são rows de timeline: `tool_chip` / `subagent_chip` / chamadas de grupo / `task_snapshot_card` sem `.border` / `.rounded` / fill. Cada row é `CHIP_HEIGHT` (28px) com slot de ícone de 18px, sem spine; `stream_event_row` centraliza altura, baseline e tipografia e copy verbo+objeto em sans regular de 14px/22px, ação em `text_muted` e detalhe/path/comando em `text_faint` (falhas conservam tons semânticos), igual à escala do corpo, com 4px entre blocos (`stream_copy`: basename em Read/Write/Edit, `Ran command`/`Running command` + resumo curto em sans, `:` em Search/Glob/Web). Sem placa Success/Failed. Chevron de tool/turno fica invisível em repouso e aparece só no hover do próprio header (reasoning é a exceção: seta sempre visível), reservando espaço para não deslocar texto. Fica imediatamente após o conteúdo, não no limite da coluna: labels encolhem para truncar, mas não crescem para consumir o espaço livre. Tools genéricas `Unknown` mostram ícone + nome, sem `Ran tool`/`Running tool`; o nome sozinho usa `text_muted` e conserva truncamento. Labels semânticos, falhas e estado ativo são preservados. Eval JavaScript/Python omite `js ·`/`javascript ·`/`py ·`/`python ·` redundante porque o ícone já identifica a linguagem. Hover de spawn ainda lava com `ink(0.04)`. Não reintroduzir card `hairline(0.07)` nem `ink(0.08)` no ícone.
- Payload expandido de tool (invocação + resultado) usa uma única superfície de código com borda, raio 8px e fundo discreto. Exec expandido inclui o header na mesma moldura, sem duplicar o resumo fora dela; comando curto cabe no detalhe sans, composto/longo resume até quatro executáveis pelo scanner de `tool_icons`, com corpo de heredoc fora do resumo. Invocação completa permanece no payload monoespaçado. Payloads usam altura natural do texto quebrado, viewport vertical até 360px e 8px de espaço após cada card expandido; não usar altura fixa por contagem de linhas nem tween que recorte o texto ao reflow. `tool_payload_scrolls` retém o `ScrollHandle` por detalhe e limpa na troca de Chat. Comando e output preservam indentação, quebram linhas pela largura disponível e usam apenas scroll vertical, sem ellipsis por linha; diff mantém o renderer semântico e limites/sidecars continuam explícitos.
- A adoção nativa de Agent Elements P1–P6 está mapeada em `docs/agent-elements-adoption.md`: `stream_event_row`/`stream_disclosure` são a base compartilhada; Write/Edit especializam o card; payload, Markdown e diff usam a escala de código de `markdown::render`. Write/Edit seguem `EditToolDiffCard`: o fill do header arredonda seus próprios cantos (7px internos para moldura de 8px/1px), pois `overflow_hidden` no GPUI recorta só um retângulo; sem preview, arredonda também embaixo. Os fundos e rails das linhas do diff são faixas de um único contorno do viewport: o canvas estacionário fica fora do scroller, preservando os cantos inferiores inclusive com scroll e virtualização. Moldura única, header de 28px com texto 12px e stats monoespaçadas 11px à direita; seta continua junto ao nome e só no hover. Fundo neutro `ink(0.035)` compartilhado com os cards de comando, inclusive o header; diff unificado com colunas antiga/nova e +/−; números relativos ao trecho são omitidos em caudas truncadas ou linhas quebradas para pintura. Sem rodapé separado de expansão: abrir/recolher permanece no header, e o diff termina no contorno inferior arredondado, sem faixa preta reservada. Preview recolhido até 72px, expansão até 200px com scroll/virtualização e lazy fetch existentes; linhas longas quebram dentro da coluna de código, sem scroll horizontal; números e sinais ficam no topo da linha lógica e o fundo cobre toda sua altura/largura. Gutters usam a largura dos dígitos e só os lados numerados presentes (Write não reserva coluna antiga; cauda sem números não reserva gutters vazios), com padding esquerdo de 8px e gaps de 4px. Trechos curtos usam altura natural limitada e arquivos grandes usam `ListState` de alturas variáveis, remedido ao redimensionar; conteúdo/rodapé novo invalida as alturas retidas. Falhas de Write/Edit/Todo usam o detalhe genérico para não esconder diagnóstico; saída de falha tem precedência sobre diff/stats.
- A projeção suprime erros idênticos e paths de imagem repetidos **por entry**, sem alterar o doc. - **Toda mutação de sessão entra numa fila; nenhuma é descartada.** `WorkersModel::run_action` tinha `if self.action_task.is_some() { return; }` — um mutex de um slot que engolia o comando **sem erro, sem log**. Skip limpa **todas** as páginas (pick velho iria como resposta real) e nunca é gated por `can_advance`: é a única saída de uma pergunta que o usuário não quer responder.
- **Mermaid rendering com beautiful-mermaid embutido**: o layout e geração SVG usam o motor `beautiful-mermaid` (baseado em ELK) embutido no binário via QuickJS (`rquickjs`), com resolução estática de variáveis CSS para compatibilidade direta com o pipeline SVG do gpui. Blocos `mermaid`/`mmd` assentados renderizam inline de forma contínua no fluxo do markdown (sem card wrapper pesado de erro). Botão flutuante de maximizar surge no `hover` do canto superior direito. Ao clicar no diagrama ou no botão de maximizar, abre o `mermaid_lightbox` modal com controles de zoom (In, Out, Fit, 1:1), cópia de SVG e código fonte, e suporte a `Esc`. Falha de sintaxe faz fallback silencioso para o bloco de código comum com destaque de sintaxe.
- **Diagrama inline é FIGURA ajustada, nunca recortada**: o bloco reclama as duas goteiras da row (`mx(-COLUMN_GUTTER)`, largura AUTO — `w_full` resolveria 100% da coluna e só deslocaria a caixa) e o desenho é ajustado a essa largura por um frame com `aspect_ratio` + `max_w(natural * INLINE_MERMAID_SCALE)`, com o `img` em `size_full`. O `aspect_ratio` mora no frame porque o gpui substitui dimensão AUTO do `img` pelo tamanho natural do raster antes do taffy (`Img::request_layout`) — era isso que fixava a altura no natural e deixava o desenho letterboxed dentro de uma caixa mais alta. Como `w_full` nunca excede o bloco, não existe overflow: nada de scroll container, `ScrollHandle` por row ou `edge_faded` — o `justify_center` de antes centrava conteúdo mais largo que o scroller e cortava os DOIS lados, com a esquerda inalcançável. O engine também renderiza com `MERMAID_FRAME_PADDING` (12) em vez do default 40: 80px de largura morta empurravam um flowchart que caberia para fora da coluna. Diagramas ganham presença e conforto visual inline com `INLINE_MERMAID_SCALE` (1.25).
- **`icons::icon` só pinta com `text_color` no PRÓPRIO svg**: `gpui::Svg::paint` faz `self.path.zip(style.text.color)` sobre o estilo computado do próprio elemento, e `compute_style_internal` parte de `Style::default()` — cor no div pai **não** cascateia. Ícone sem cor não é ícone apagado, é nada pintado, sem log: foi assim que a lightbox do mermaid ficou com botão de fechar invisível e o botão de expandir virou um quadrado preto vazio. Cor (e `group_hover` de cor) vai no `icon(...)`, nunca só no wrapper.
- **A lightbox do diagrama tem UM canal de ação**: `MermaidPreviewAction` + um `on_action`, não uma closure por controle. A assinatura anterior tinha sete closures e era exatamente onde um controle desconectado se escondia; hoje `zoom`, `pan`, cópia e fechamento entram todos por `Transcript::on_mermaid_preview_action`, que é o único lugar onde zoom e pan são clampados **juntos** (zoom out encolhe o slack, então pan de um zoom mais fundo abandonaria o desenho fora do canvas).
- **Abrir a lightbox usa `fit_zoom`, nunca `1.0`**: diagrama maior que a janela abria recortado nos quatro lados sem nada na tela que alcançasse o resto. `Fit` recalcula pelo viewport corrente e o teto é `MAX_FIT_ZOOM` (2.0 = escala do raster SVG do gpui; além disso só borra). Gestos: **pinch** dá zoom (`on_pinch`, `magnifyWithEvent:` → `PinchEvent` no `gpui_macos`), scroll de dois dedos faz **pan**, ⌘/ctrl + scroll dá zoom pra quem está no mouse. Wheel puro dando zoom era o oposto: redimensionava sem pedir e não sobrava gesto pra mover.
- **Imagem inline é a imagem, sem moldura**: sem card, sem borda, sem barra de nome — só o `img`, com **altura absoluta** (`INLINE_IMAGE_HEIGHT`) e largura AUTO, porque é a única combinação que o gpui deriva do ratio intrínseco (`Img::request_layout`); largura em porcentagem deixaria a altura no natural e voltaria a letterboxar. A altura fixa é o que mantém a row analítica pro virtualizador, então o estado `Reloading` ocupa a mesma caixa.
- **GPUI Dev Inspector é exclusivo de development builds (`debug_assertions`)**: `inspector.rs` é gateado sob `#[cfg(debug_assertions)]`, ativado por atalho `cmd-alt-i` (registrado em `shell::apply_keymap`) ou menu `Developer -> Toggle GPUI Inspector`. O renderer monta um painel com botão de picking (`inspector.start_picking()`), exibição de `source_location` (`file:line`), `instance_id` e cópia para clipboard, mais os estados dos elementos inspecionados (`inspector.render_inspector_states`). Compilação em release exclui completamente o módulo e suas chamadas sem qualquer overhead.
- **Worked Projects no card Workspace é uma projeção pura do transcript**: `details_sidebar/worked_projects.rs` deriva somente de `&[SessionMessageEntry]`, `&[WorkersProject]`, do checkout do chat e de `home_dir`. Casamento filtra grupos organizacionais (`!is_group`), calcula Leaf Roots sobre todos os projetos registrados antes de excluir o own checkout, ignora caminhos relativos, expande `~/` com home dir e respeita fronteira de componente (`/a/kanna` não casa raiz `/a/kanwas`). O bloco só aparece em `DetailsMode::Orchestrator` com contagem > 0, empilha sem gap vertical e o resultado é memoizado em `DetailsSidebarState` por (context key, transcript length, total de parts, fingerprint de projetos). O total de parts não é redundante: `TranscriptFrame::Delta` faz upsert da MESMA entry por id, então `transcript.len()` não muda enquanto uma nova part `ReadFile`/`Exec` entra — sem essa dimensão o card congela pelo turno inteiro.
- **Chat Trajectory Preview (`trajectory/`) é surface de inspeção analítica e técnica no pane direito**: `TrajectoryView` é dona do próprio watch task (`subscribe_checked`) e retoma histórico/live por watermark (`TrajectoryCursor`); estados terminais (`ChatDeleted`, `StoreUnavailable`) selam o stream e impedem reabertura. `AppState` apenas expõe o handle da engine para emissão de RPCs (`WatchTrajectory`, `RevealTrajectoryRaw`) e nunca retém estado de surface fechada. Raw Reveal (`RevealState`) é estritamente efêmero no dispositivo local e nunca persiste nem sincroniza; troca de seleção ou fechamento limpa o estado. `ROW_HEIGHT` no ledger é fixo (`px(26.0)`) e nenhum estado altera a altura da linha. Dado ausente renderiza como `Unavailable` ou `Unsettled`, nunca como zero ou vazio fabricado.
- **Settings → Projects mostra o LEDGER, nao o working set.** A sidebar de
  Workers lista `projects[]`, que `remove_project` poda junto com as sessoes;
  esta pagina lista `zeron_workers_unpeel::project_ledger`, que sobrevive a
  poda. Uma linha so do ledger nao tem `project_id`: renomear, "Fill with AI" e
  "Run Auto Doc" ficam indisponiveis nela porque nao ha o que lancar. O
  "Forget" do Danger Zone apaga metadado e NAO toca em sessao — e o verbo
  oposto do "Remove project" do menu de contexto da sidebar. Grupos
  organizacionais compartilham o path do pai e ficam fora; worktrees de path
  próprio continuam. A lista rola no próprio pane.
- **O verbo de remoção pergunta `is_group`, não `parent_project_id`.** Menu
  (`project_menu.rs`), label do confirm (`workspace.rs`) e dispatch
  (`WorkersModel::remove_project`) leem o MESMO veredito da projeção:
  `worktree_branch` → `remove_worktree`, `is_group` → `remove_group`, resto →
  `remove_project`. Ter pai não é ser organização — worktree adotado ganha
  parent do disco e, sem branch no registry (HEAD destacado), cairia em
  `remove_group` e morreria em "project is not a group". As três metades têm
  que concordar, senão o label promete uma remoção que o host recusa.
- **Git so roda para o projeto SELECIONADO.** `status` e os dois commits
  ancora custam processos; a listagem nunca os chama. E `RepositoryState` tem
  um quarto estado que o reference nao tem — `FolderMissing` — porque o ledger
  guarda projetos cuja pasta o usuario pode ter movido: sem ele, uma pasta
  apagada leria como "nao e repo" e ganharia um Initialize Git que falharia.
  Link de repository preserva `GitRemote.host`; nunca reconstrói tudo em
  `github.com`.
- **Config/Worktree são editor, não resumo.** Target suportado + listas shared,
  Unix e Windows normalizam linhas vazias/comentários e só gravam quando o
  conteúdo ou target mudou. Saves são serializados; enquanto um está em voo,
  a fila preserva o draft mais novo por projeto e só avança o baseline depois
  da persistência correspondente. Ícone usa SHA-256 do path, é carregado fora
  do render e reset/forget só podem remover filho direto do diretório app-owned.
- **Falha de setup e sucesso parcial visível.** O worktree criado continua
  selecionável, mas comando + motivo entram em `WorkersModel.error`, sobrevivem
  ao refresh seguinte e nenhum Worker é lançado automaticamente nele.
- **Settings → Accounts renderiza provedores na ordem fixa Claude, Codex, Kimi,
  Antigravity, Cursor, Grok.** Contas gerenciadas (Kimi Code, Antigravity, Grok)
  chegam da engine `active: true, switchable: false`; a linha não expõe Add
  account, Switch nem Forget, e a autenticação permanece nos CLIs. Cursor
  mantém slots pelo SDK mas recebe janelas de quota da sessão desktop
  (`state.vscdb`), anexadas por matching de email. Cada row tem um toggle de
  Usage (default ON): id em `UiSettings.usage_widget_hidden_account_ids` some do
  widget; meters na página Accounts continuam. O headline do widget deriva da
  janela primária (semanal se houver, senão a primeira), permitindo que ciclos
  mensais como o do Cursor exibam seu próprio label (`Monthly N%`) sem cair no
  placeholder `—`.

- Browser native frames retain fractional points; the overlapping five points at the left edge yield to the shell divider. The divider paints after its pane while Details remains a separate adjacent column.
- Composer focus is requested once on navigation, attachment completion/cancel and picker completion/Escape. Clicking away keeps a neutral mounted shortcut target; repaint must not return the caret. Preview lightbox focus remains independent. Terminal selection requests focus after mounting.

- Completion sounds/banners consume new Session completion markers, never infer success from Idle. First observations, stale updates and pending sends update the baseline silently. AwaitingInput notifications remain independent; compaction uses the same completion evidence.

- **Projeto vazio não é seleção automática de Workers**: `apply_snapshot` nunca escolhe o primeiro registro como fallback. Ao desaparecer a última sessão do projeto selecionado, a seleção implícita é limpa (inclui archive/remove local e refresh de alteração externa). Projeto vazio selecionado explicitamente ou com launch pendente continua acessível; o ledger e os arquivos não são removidos.
