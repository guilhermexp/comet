## Integration decisions

Real `--no-ff` merge of `d5a01522` after formatting our side (base `c526d6f7`). Conflicts are resolved file by file against base/fork/upstream, preferring upstream structure with the minimum patch to keep fork behavior. Refused content resolves to the fork side inside the merge so the next sync does not see it again. Version bump commits stay in ancestry without changing 1.0.10; `Cargo.lock` is regenerated by cargo. The incoming-additions audit compares only `c526d6f7..d5a01522`.

### D1: Cloud dormant, provider switching live

Cloud code (`runner.rs`, `credentials.rs`, `cloud_client.rs`, `CloudRunner`, Cloud/Billing settings, `CheckoutKind::Cloud`, iOS `Cloud/*`) may compile in but stays inert: no `ZERON_RUNNER_*` means `EngineCore::cloud` is `None`, and the UI only offers Cloud when the status comes back available. Live: `MessagePart::Switch`, `provider_sessions`, `resume_for`, transcript divider, provider/account rules in proto/client, iPhone model picker, `Auth::quiesce_refresh`. Edge: `.github/workflows/deploy.yml` and `edge/wrangler.jsonc` stay fork; new `edge/src/cloud/*` and `edge/vault/**` only remain if typecheck/test pass without new bindings, otherwise they stay out of the graph imported by `index.ts`.

### D2: IPC bearer accepted, background engine refused

Accept `rpc/ipc_auth.rs`, `serve_ipc`, `connect_ws(url, token)`, `connect_ipc` and WS fragmentation. Every fork client gets the token: `sessions-mcp`, `zeron mcp`, `workers-unpeel`, `auth_cli`, `sync_cli`, fixtures and tests. Refuse `engine/managed.rs` wiring, `zeron-engine` binary, `apps/zeron/src/background.rs`, reduced `main.rs` and the `Zeron Engine` packaging; upstream code needed to compile may stay dormant.

### D3: Muse Code without MCP

`HarnessId::Muse` gets an arm in every fork `match` (OMP/Kimi included). `MuseHarness` holds `RunControls.execution_lease` for the whole turn. No MCP grants for Muse.

### D4: CLI updates through the owner

Unify fork `UpdatePlan::PackageManager{program,args,env}` with upstream `Package{owner,..}`/`Homebrew`, keeping brew/Caskroom/npm prefix, OMP (`omp update`, `--no-extensions`), Antigravity and `update_lease`/`execution_lease`. Pi keeps `pi update --all`. The compatibility feed never reads `zeron.sh`/`*.zeron.sh`: it uses the fork release base (`edge_release_base`/`COMET_RELEASES_URL`) and a 404 means no known-bad list.

### D5: Native subagents switch only through the grant

`RunRequest.mcp` stays empty. `side_chats_only`/`ZERON_SIDE_CHATS_ONLY=1` and `--disallowedTools=Agent,Task,Workflow` only apply when the run has the fork `sessions` grant (the replacement tool exists). If it cannot be done cleanly the code stays dormant with native subagents always on and the Settings page hidden, recorded as refused.

### D6: Close a question without answering

`answers: Some([])` only when the question was closed without ever having an answer. Cancel never erases a recorded answer; absence stays distinct from empty. `crates/doc/AGENTS.md` records the final rule.

### D7: Terminal latency and device link

Take engine/UI terminal latency work, `TCP_NODELAY`, predictive echo, host query replies, WebRTC link between the user's devices and the `zeron-term`/`zeron-term-link` crates. Terminal stays in the right panel only. Workers terminal (`crates/ui/src/workers/terminal.rs`) is ported to the new input API; `terminal/scroll.rs`, `retain_last_alternate_screen` and `panel.rs` (`embedded`, `render_context`, `resize_suspended`) are preserved. Root `AGENTS.md` states the terminal RTC exception.
